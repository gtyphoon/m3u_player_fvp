# M3U 多路监控播放器（M3U Player）

一个把多路视频流**放在一个屏幕上看**的多画面播放器。播 **IPTV、直播、监控摄像头**都行（RTSP / HTTP-FLV / HLS 等任意 M3U 视频源），支持 **Android 手机 / Android 电视盒 / Windows 电脑**，一套代码、三种设备都能用。

> 🎯 **对哪种视频流支持最好？** 本软件专门为 **H.265/HEVC 编码**的视频流做了优化——这是现在绝大多数监控摄像头和不少 IPTV 源默认的输出格式（尤其是 **HEVC-in-FLV** 封装）。对这种流，软件支持**硬件解码**（用手机/电视/电脑自带的视频芯片解码，而不是靠 CPU 硬算），做到**多路同时播放依然清晰流畅、不卡顿不发热**。当然，常见的 H.264 编码流也完全支持。

> 大白话解释：平时看视频一次只能看一路，这个软件可以把一堆视频地址整理成一个清单（M3U 文件），然后**一个屏幕同时看多路**——看多少路由你定：**1~16 路任意调节**（比如 4 路、9 路、16 路），行列布局也能自由设置（自动或固定行数）。还能一键切换"清晰/流畅"码流、按分组切换、翻页预加载、**双击任意画面单路全屏**（当大屏播放器用）。

### 🎬 支持什么视频（格式支持矩阵）

**先看播放链路**（三层，各干各的）：
**fvp**（Flutter 插件，负责"把画面显示到界面"）→ **MDK**（播放内核，负责"调度解码"）→ **FFmpeg**（解码器，负责"把视频数据变成画面"）。
MDK 和 FFmpeg 不是单独的插件，而是**随 fvp 一起打包的底层引擎**——你在 `pubspec.yaml` 里只会看到 fvp 这一个播放相关的依赖，打开安装包文件夹则会看到 `fvp.dll`（Flutter 插件）、`mdk.dll`（播放内核）、`ffmpeg-9.dll`（解码器）。

**视频编码：**

| 分类 | 编码 | 播放方式 |
|------|------|---------|
| 监控主打（最擅长） | **H.265 / HEVC**（含 HEVC-in-FLV）、**H.264** | 硬件解码 + 软件解码兜底 |
| FFmpeg 软件解码全覆盖 | H.263、MPEG-2、MPEG-4（DivX/Xvid）、VP8/VP9、AV1、WMV、VC-1、MJPEG 等 | 软件解码 |

**音频编码：** AAC、MP3、AC3/E-AC3、FLAC、Opus、Vorbis、PCM 等常见格式。

**封装格式：** FLV、TS、MP4、MKV、MPEG-PS、AAC 等。

**传输协议：** RTSP（监控主流）、HTTP-FLV / RTMP（拉流主流）、HTTP(S) 直连、HLS（m3u8）、UDP 等。

**硬件解码说明：**
- Windows：走 Media Foundation（MFT）硬解 H.264 / HEVC / MJPEG；VP9 / AV1 / 部分 HEVC 需要设备装了微软商店的免费解码扩展。
- Android：走系统 MediaCodec 硬解。
- 硬解失败或不可用时**自动回退软件解码**；控制面板里也可以手动切换"自动 / 硬解 / 软解"。

> 一句话：**IPTV / 直播 / 监控都能用**——H.265 + H.264 编码、RTSP / HTTP-FLV 协议的组合是优化重点；其它常见格式也能播（软件解码）。

## 三、频道清单 M3U 怎么写

M3U 本质上就是一个**纯文本文件**（用记事本或 VS Code 编辑，保存时编码选 **UTF-8**），每条频道占两行：第一行 `#EXTINF` 开头是频道的描述，第二行是播放地址。

### 最简单的例子

```
#EXTM3U
#EXTINF:-1 group-title="教室1",一号教室
http://192.168.1.10:8080/live/ch01
#EXTINF:-1 group-title="教室2",二号教室
http://192.168.1.10:8080/live/ch02
```

### 分组（把频道分门别类）

`group-title="分组名"` 就是分组名，软件里按"分组"按钮就能切换。**用分号 `;` 分隔分组名和码流名**：

```
#EXTINF:-1 group-title="教学楼;清晰",101教室
http://10.0.0.11:8080/live/101_0
```

### 清晰 / 流畅 双码流（同一个摄像头两个地址）

**先说明软件的真实规则**：清晰/流畅的区分，**完全由 `group-title` 分号后面的"码流名"决定**，跟播放地址的后缀**没有关系**。切换"码流"时，软件做的是：把码流名等于当前选择的频道挑出来播放。

```text
#EXTINF:-1 group-title="教室1;清晰",教室1号机
http://192.168.1.10:8080/live/ch01_0
#EXTINF:-1 group-title="教室1;流畅",教室1号机
http://192.168.1.10:8080/live/ch01_1
```

上面例子里两条地址的结尾 `_0` / `_1` **只是常见的摄像头地址命名习惯**（很多摄像头厂商习惯用 `_0` 表示主码流、`_1` 表示子码流），软件本身不检查、也不要求地址必须这样命名——你的摄像头地址叫什么就填什么，两个地址可以是完全不同的写法，只要 `group-title` 分号后面的码流名分别写了"清晰"和"流畅"即可。

**清晰/流畅通常对应什么**（取决于你的摄像头怎么配）：

| 码流名 | 常见含义 | 特点 |
|--------|---------|------|
| 清晰 | 主码流（通常是 H.265/HEVC 编码） | 画质好、占带宽高 |
| 流畅 | 子码流（通常是 H.264 编码） | 画质一般、更省流量更流畅 |

> 本软件对 H.265/HEVC 编码的摄像头流（尤其 HEVC-in-FLV）支持得很好，支持硬解，画质清晰的同时还流畅。码流名也可以自由命名（比如"高清""标清"），不限于"清晰/流畅"两个词，只要控制面板里选的名字和清单里的码流名一致即可。

> 注意：
> - 一个频道只识别**第一个** `group-title`。
> - 没有写分组名的频道，会归入"全部"分组。

## 四、配置说明

你在控制面板里调的所有参数，软件都会自动保存，下次启动自动恢复。

| 平台 | 配置文件位置 |
|------|-------------|
| Windows | exe 旁边的 `config.ini`（文本格式，UTF-8 编码） |
| Android | 应用内部存储（卸载软件才会清掉） |

### Windows 的 config.ini 里都有什么

用记事本打开 `config.ini`，会看到类似：

```ini
layout=2
preload=0
group=全部
quality=清晰
orientation=landscape
decoder=auto
probesize=32768
analyzeduration=20000
nobuffer=true
```

| 键 | 含义 | 可选值 |
|----|------|--------|
| layout | 布局（几行几列） | 数字 |
| group | 当前分组 | 你的分组名 |
| quality | 码流 | 清晰 / 流畅 |
| orientation | 屏幕方向 | portrait（竖）/ landscape（横）/ auto |
| decoder | 解码方式 | auto / hard（硬解）/ soft（软解） |
| probesize | 播放器探测大小（字节） | 数字 |
| analyzeduration | 分析时长（微秒） | 数字 |
| nobuffer / flush_packets | 低延迟开关 | true / false |
| first_frame_timeout | 首帧超时（秒） | 数字 |
| heartbeat_timeout | 心跳超时（秒） | 数字 |

> 提示：升级软件时，把 `config.ini` 一起保留/备份，参数就不会丢。旧版本存在 `%APPDATA%\m3u_player_fvp` 的配置，新版首次运行会自动复制到 exe 目录（不会删除旧文件）。

## 五、项目结构（每个文件是干嘛的）

```
m3u_player_fvp/

│   └── native_player.dart        ← 播放内核封装（硬解/软解、超时参数）

├── windows/                      ← Windows 工程文件（一般不用动）
├── test/
│   └── widget_test.dart          ← 自动化测试
├── pubspec.yaml                  ← 项目"身份证"：版本号、依赖库清单

├── THIRD_PARTY_LICENSES.md       ← 第三方开源组件许可声明（发布时必须一起带上）
├── LICENSES/                     ← 各第三方组件的许可原文（fvp、FFmpeg 等）
└── LICENSE                       ← 开源许可（MIT）
```

> 对不懂开发的人来说：**日常改东西只碰两个文件就够了**——想改频道列表就改 `my_channels.m3u`，想改版本号就改 `pubspec.yaml`。其余文件看看就好，不用动。

## 六、技术栈

## 七、常见问题

**Q1：双击 exe 没反应 / 提示缺少 DLL？**
A：确认你用的是解压后的完整文件夹（不要只把 exe 单独拷出来），文件夹里的 `data`、`fvp.dll` 等文件缺失时软件起不来。

**Q2：画面一直"连接中"？**
A：检查摄像头地址在浏览器里能不能打开；确认手机/电脑和摄像头在**同一个网络**（监控一般只在局域网内访问）；尝试在控制面板把"解码方式"从自动切换为"硬解"或"软解"。

**Q3：我改了 my_channels.m3u 但软件里没变化？**
A：软件只在启动时加载清单。改完文件后**重启软件**；或者在控制面板里点"加载 M3U 文件"重新导入。另外注意文件编码要存成 **UTF-8**。

**Q4：构建时报 `ndk.abiFilters` 相关错误？**
A：去 `android/app/build.gradle.kts` 里确认没有写 `ndk { abiFilters ... }`，删掉后重新构建。

**Q5：Windows 上想恢复默认设置？**
A：控制面板里点"重置所有参数"，或者关掉软件后删除 exe 旁边的 `config.ini` 再启动。

**Q6：遥控器（电视盒）方向键不听话？**
A：确认设备是否支持遥控器输入；在控制面板检查"电视模式"设置（auto 通常能自动识别）。

**Q7：老电视/老手机提示"解析包错误"或安装不上？**
A：本软件要求 **Android 7.0（API 24）及以上**，Android 6.0 及以下的设备不支持。请先在"设置 → 关于本机 → Android 版本"确认系统版本；如果设备系统太低，只能换设备或用 Windows 版。
